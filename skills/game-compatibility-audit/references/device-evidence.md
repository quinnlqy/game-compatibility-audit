## 高频与优先级不能混用

来源项目中，布局遮挡/有效高度反复最多，其次是输入与滚动、横屏平板排布；这是修复记录的定性归纳。新游戏应先保护启动、主流程与存档/消费，随后按实际阻断程度处理关键操作和视觉问题。一次泛化审核文案不计为多个确定缺陷，反复打包验证也不计为新增投诉。

## 跨 UI 工具影像补充（2026-10-18）

用户提供两张录像截图：已拿起夹子，手指在材料 UI 上时夹子不显示，移入蛋糕画面又显示。未提供本次设备型号或明确平台，不据状态栏猜测。三个独立最新 ZIP 均可本地复现：JS 排除了触屏 UI 预览，移动样式再次隐藏预览，指针捕获还会让 event.target 一直指向 canvas。

确认的处理是让已有透明工具预览覆盖 DOM UI，脱离被裁剪/变换的容器，使用真实命中判断画布与 UI，并保持 pointer-events:none；画布内继续原 3D 绘制。检查工具图像真的加载且可见、材料仍可拾取、捕获后返回 UI、取消/失焦/放下清理、库存与撤销重做。初次修复验证又发现单页宿主退出后脱离容器的节点残留，补会话销毁清理节点和新增监听，并实际确认放弃后重复退出重进。单独提高 canvas z-index 不能让像素越过 canvas 自身边界。该问题属于 I02/I03 的跨区交接与可见性回归，不能直接认定就是此前 OPPO 用户的原始原因。

## 小红书重复审核反馈补充（2026-10-19）

用户确认 v32 r4 仍被同一句“可能页面按钮无法点击”拒绝，没有更多按钮/步骤。已有多视口与全解锁专项不能当空存档或宿主异常完整性证据。该实际 ZIP 的受控原生存储夹具复现：主档已保存但备份 Promise 永不结束，解锁按钮一直等待；主写返回成功却未写入时，界面误显示配方已拥有；主写挂起也无等待上限。

改为主写有界等待与回读确认、可选备份脱离前台等待、迟到未完成写跨存储实例保持同键保护，再从真实按钮重试并验证金额/收据仅一次。备份串行合并最新值以防旧备份乱序覆盖。健康路径和故障恢复均要测试。上述是本地确认缺陷，不能据此宣称已找出平台审核原因；真实手机/官方宿主仍待验证。首次配方页落在未解锁条目属于产品引导与合法前置条件，和点击被遮挡分别记录，不擅自放开解锁规则。
